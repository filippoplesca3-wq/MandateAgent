# Deploying Agent Mandate

The app is one Node process. Express serves both the API and the built React
console from `dist/web`, reads `PORT`, and keeps the agent-endpoint rate limit
enabled. The hosted demo needs **no PayPal or Gemini credentials**: it serves
`replays/demo-run.json`, a recording of a real Gemini run, and every write
endpoint is read-only.

## Build and run locally (production shape)

```bash
npm ci --include=dev
npm run build
REPLAY_FILE=replays/demo-run.json npm start
# Windows PowerShell:
# $env:REPLAY_FILE="replays/demo-run.json"; npm start
```

Open `http://localhost:3001`. The health check is `GET /api/health`.

## Render (free tier, blueprint)

`render.yaml` is already in the repo.

1. Push the repository to GitHub.
2. In [Render](https://render.com), choose **New → Blueprint**.
3. Connect the repository and apply the blueprint.
4. Wait for the build. Render gives you a URL such as
   `https://agent-mandate.onrender.com`.
5. Open the URL. Free web services sleep after inactivity; the first request
   can take 30–60 seconds to wake the instance. That is expected.

The blueprint sets:

| Setting | Value |
| --- | --- |
| Build | `npm ci --include=dev && npm run build` |
| Start | `npm start` |
| Health check | `/api/health` |
| `REPLAY_FILE` | `replays/demo-run.json` |
| `MANDATE_SIGNING_KEY` | generated by Render (`generateValue: true`) |
| `NODE_VERSION` | `22` |

No PayPal or Gemini credentials are required, and none should be added to a
public demo. Render generates the signing key once and keeps it, so the published
Ed25519 public key is stable across restarts.

### What the hosted replay does and doesn't do

The hosted build is a **read-only recording** of a real Gemini run. It starts
with a pre-seeded demo mandate, so judges do not need an admin token or an
"issue mandate" step.

- **Works:** playback of the recorded run, the mandate view, the dry-run
  "Test a payment" presets, the audit ledger and the seller view.
- **Disabled:** issue, revoke and approve. The UI disables those buttons, and
  the API refuses writes with `409` because a recording must not be edited. That
  is why `ADMIN_TOKEN` is deliberately not set on the public blueprint.
- **Not available:** a fresh Gemini run and the live PayPal sandbox checkout.
  Both need credentials, which must never be placed on a public demo.
- **Ephemeral state:** the store is in memory and the free instance sleeps.
  Every wake starts a fresh demo mandate, so mandate ids are ephemeral even
  though the signing key is stable. Warm the URL before judging and expect
  30–60 seconds on the first request.

To exercise issue / revoke / approve or the live sandbox path, run locally — see
"Build and run locally" above and the README's live-mode section.

### Optional environment variables

| Variable | Effect |
| --- | --- |
| `REPLAY_FILE` | Serve a recording. Remove it to run simulated mode instead. |
| `MANDATE_SIGNING_KEY` | Secret used to derive the Ed25519 key. Set it to keep the public key stable; on Render the blueprint generates it. |
| `ADMIN_TOKEN` | Enables issue / revoke / approve outside replay. In replay those routes are refused with `409` regardless. |
| `ALLOWED_ORIGINS` | Comma-separated exact origins allowed to call the API cross-origin. |
| `RATE_LIMIT_PER_MINUTE` | Per-IP limit on `/api/agent/run` and `/api/evaluate` (default 30). |
| `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET` | Enables the live **sandbox** toolkit. |
| `PAYPAL_MERCHANT_ALIASES` | Maps a sandbox merchant id to the mandate's merchant name. |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Lets the server run Gemini. Do not put a key on a public demo. |

Live mode is used only when the PayPal credentials are present. Without them the
app stays simulated. Keep `PAYPAL_ENVIRONMENT=SANDBOX` on any public deployment;
`check:live` refuses to run against live money.

## Railway (free trial)

1. In [Railway](https://railway.app), choose **New Project → Deploy from GitHub**.
2. Select the repository.
3. Set the build command to `npm ci --include=dev && npm run build` and the start
   command to `npm start`.
4. Add `REPLAY_FILE=replays/demo-run.json` and `NODE_VERSION=22`.
5. Generate a public domain under **Settings → Networking**.

Railway injects `PORT`; the app already reads it.

## Docker (alternative)

The repo includes a `Dockerfile` that mirrors `npm ci && npm run build` and runs
as the unprivileged `node` user:

```bash
docker build -t agent-mandate .
docker run --rm -p 3001:3001 \
  -e REPLAY_FILE=replays/demo-run.json \
  -e MANDATE_SIGNING_KEY="$(openssl rand -hex 32)" \
  agent-mandate
```

Open `http://localhost:3001`. For SQLite persistence add
`-e STORE_BACKEND=sqlite -v agent-mandate-data:/app/data`.

The image keeps dev dependencies because `npm start` runs TypeScript through
`tsx`; it is a demo image, not a hardened production build.

## Keep the free instance warm

`.github/workflows/warm.yml` pings `/api/health` every 10 minutes, but only when
the repository variable `DEMO_URL` is set:

1. Open the repository on GitHub.
2. **Settings → Secrets and variables → Actions → Variables → New variable**.
3. Name it `DEMO_URL` and use the Render URL without a trailing slash, for
   example `https://agent-mandate.onrender.com`.

Render's free tier includes 750 instance hours per month; one always-on service
uses about 730. Remove the variable or disable the workflow if you run other
free services. Without it, warm the URL manually before judging.

## Troubleshooting

- **First load is slow** — Render free instances sleep. Wait for the wake-up,
  and warm the URL before judging.
- **The demo reset** — free instances keep state in memory; every restart starts
  a fresh pre-seeded mandate. Mandate ids are ephemeral by design.
- **`/api/health` fails** — check the build log; Node must be 22 or newer.
- **Issue / approve is disabled or returns 409** — the hosted build is a
  read-only replay, so writes are refused on purpose. Run locally to issue,
  revoke or approve.
- **Issue / approve returns 503** — the server is not in replay and
  `ADMIN_TOKEN` is unset. That is the fail-closed default. Set it and enter the
  same token when the UI prompts.
- **Agent run returns 502** — no server Gemini key and no key supplied in the
  UI. The replay demo does not need one.
- **A live capture is refused with `MERCHANT_NOT_ALLOWED`** — set
  `PAYPAL_MERCHANT_ALIASES` so PayPal's merchant id maps to `acme-supplies`.
